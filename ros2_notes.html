01

Create a node

Include the ROS client library, inherit from rclcpp::Node, then spin your node.

src/my_node.cpp · includes
#include <chrono>
#include <functional>
#include <memory>
#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/string.hpp"

using namespace std::chrono_literals;
Define + run
class MyNode : public rclcpp::Node {
public:
  MyNode() : Node("my_node") {
    // Create publishers, subscriptions, timers here.
  }
};

int main(int argc, char * argv[]) {
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<MyNode>());
  rclcpp::shutdown();
  return 0;
}
02

Publish + subscribe

Both nodes use the same topic name and message type. Keep publisher and subscription handles as class members.

Publisher · member and constructor
rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_;

publisher_ = create_publisher<std_msgs::msg::String>(
  "chatter", 10);
Publish a message
auto message = std_msgs::msg::String();
message.data = "Hello, ROS 2";
publisher_->publish(message);
Subscriber · member and constructor
rclcpp::Subscription<std_msgs::msg::String>::SharedPtr subscription_;

subscription_ = create_subscription<std_msgs::msg::String>(
  "chatter", 10,
  std::bind(&MyNode::on_message, this, std::placeholders::_1));
Callback · inside MyNode
void on_message(
  const std_msgs::msg::String::SharedPtr msg) const {
  RCLCPP_INFO(get_logger(), "Received: %s", msg->data.c_str());
}
10 is the queue depth in these examples.
03

Timers + parameters

Timer · member and constructor
rclcpp::TimerBase::SharedPtr timer_;

timer_ = create_wall_timer(
  1s, std::bind(&MyNode::on_timer, this));
Timer callback · inside MyNode
void on_timer() {
  auto message = std_msgs::msg::String();
  message.data = "Periodic update";
  publisher_->publish(message);
}
Create the publisher before the timer that calls it. The 1s literal needs std::chrono_literals.
Declare + read a parameter
declare_parameter<double>("rate", 1.0);
double rate = get_parameter("rate").as_double();
Terminal
List parametersros2 param list
Read valueros2 param get /my_node rate
Change valueros2 param set /my_node rate 2.0
A cached C++ variable does not update itself after ros2 param set. Read the parameter again or handle parameter changes.

05

Launch files

Launch a named node with a parameter. The process action is optional.

launch/my_node.launch.py
from launch import LaunchDescription
from launch.actions import ExecuteProcess
from launch_ros.actions import Node

def generate_launch_description():
    return LaunchDescription([
        Node(
            package="my_package",
            executable="my_node",
            name="my_node",
            parameters=[{"rate": 7.0}],
            output="screen",
        ),
        ExecuteProcess(
            cmd=["ros2", "topic", "list"],
            output="screen",
        ),
    ])
Install launch files · CMakeLists.txt
install(DIRECTORY launch
  DESTINATION share/${PROJECT_NAME}
)
Terminal
colcon build --packages-select my_package
source install/setup.bash
ros2 launch my_package my_node.launch.py
06

Creating services

A service has a request and a response. Define the interface in my_interfaces and use it from C++ nodes.

my_interfaces/srv/ProcessValue.srv
int64 value
---
string result
my_interfaces/package.xml · dependencies
<buildtool_depend>ament_cmake</buildtool_depend>
<buildtool_depend>rosidl_default_generators</buildtool_depend>
<exec_depend>rosidl_default_runtime</exec_depend>
<member_of_group>rosidl_interface_packages</member_of_group>
my_interfaces/CMakeLists.txt
find_package(ament_cmake REQUIRED)
find_package(rosidl_default_generators REQUIRED)
rosidl_generate_interfaces(${PROJECT_NAME}
  "srv/ProcessValue.srv"
)
ament_export_dependencies(rosidl_default_runtime)
ament_package()
In the C++ node package, add <depend>my_interfaces</depend> to package.xml. In CMake, call find_package(my_interfaces REQUIRED) and add my_interfaces to the server and client targets' ament_target_dependencies(...).
Server · include + type alias
#include "my_interfaces/srv/process_value.hpp"
using ProcessValue = my_interfaces::srv::ProcessValue;
Server · member + constructor
rclcpp::Service<ProcessValue>::SharedPtr service_;

service_ = create_service<ProcessValue>(
  "process_value",
  std::bind(&MyServer::on_request, this,
    std::placeholders::_1, std::placeholders::_2));
Server · callback inside MyServer
void on_request(
  const std::shared_ptr<ProcessValue::Request> request,
  std::shared_ptr<ProcessValue::Response> response) {
  response->result = std::to_string(request->value);
}
Client · member + constructor
rclcpp::Client<ProcessValue>::SharedPtr client_;
client_ = create_client<ProcessValue>("process_value");
Client · asynchronous request
while (!client_->wait_for_service(1s)) {
  if (!rclcpp::ok()) return;
}
auto request = std::make_shared<ProcessValue::Request>();
request->value = 42;
client_->async_send_request(request,
  [this](rclcpp::Client<ProcessValue>::SharedFuture future) {
    RCLCPP_INFO(get_logger(), "Result: %s",
      future.get()->result.c_str());
  });
The asynchronous response callback needs the client node to be spinning. Create executable and install entries for the server and client using the node build pattern above.

Client node · wait for the result

This follows the slide's future based pattern. Run it from main() with a node that is not already spinning.

Create client + request · main()
auto client_node = std::make_shared<rclcpp::Node>("service_client");
auto client = client_node->create_client<ProcessValue>(
  "process_value");
auto request = std::make_shared<ProcessValue::Request>();
request->value = 42;
Wait + send + receive · main()
while (!client->wait_for_service(1s)) {
  if (!rclcpp::ok()) return 1;
}

auto result = client->async_send_request(request);
if (rclcpp::spin_until_future_complete(client_node, result) ==
    rclcpp::FutureReturnCode::SUCCESS) {
  RCLCPP_INFO(client_node->get_logger(), "Result: %s",
    result.get()->result.c_str());
} else {
  RCLCPP_ERROR(client_node->get_logger(),
    "Service request failed");
}
Add rclcpp::init(argc, argv); before this code and rclcpp::shutdown(); afterward. Do not call spin_until_future_complete on a node already spinning in an executor; use the asynchronous callback example above in that case.
Terminal · inspect and call
ros2 interface list
ros2 interface show my_interfaces/srv/ProcessValue
ros2 service list
ros2 service call /process_value my_interfaces/srv/ProcessValue "{value: 42}"
